# State-Based Cube Reorientation Baseline Design

## Objective

Build a state-based cube reorientation baseline before adding recurrence, domain
randomization, or learned vision. The baseline must answer one question cleanly:
can the ORCA Hand solve progressively harder orientation goals when perception is
not the bottleneck?

The work spans `orca_sim` and `orca_train`. It preserves the current visual
red-face task and its checkpoints while adding an independent, explicitly
configured path for full cube orientation control.

## Scope

This stage includes:

- Full cube-orientation goals represented by normalized `wxyz` quaternions.
- Quaternion-relative goal observations and geodesic angular error.
- Angular-progress reward that measures reduction in geodesic error.
- Control periods, target timeouts, and success holds configured in seconds.
- Three static curriculum presets: fixed single goal, random right-angle goal,
  and multi-goal orientation sequences.
- A state observation adapter, vector replay buffer, feed-forward state agent,
  training CLI, evaluation metrics, and checkpoint support.
- Unit, integration, and short training smoke tests in both repositories.

This stage does not include:

- LSTM or GRU policies.
- Asymmetric or privileged critics.
- Physics, actuator, timing, sensor, or visual domain randomization.
- A learned pose estimator, multi-camera input, or physical-hand deployment.
- An automatic long-running training launch.

Those are separate stages so that failures remain attributable to task/control,
memory, robustness, or perception rather than to a combination of all four.

## Compatibility

The existing `OrcaHandRightCubeOrientation` defaults remain behaviorally
compatible:

- `goal_mode="face_direction"` remains the default.
- The existing six red-face directions, shuffled bag, alignment reward modes,
  10 ms control period, step-based limits, observations, and info keys remain
  unchanged unless a new option is selected.
- `OrcaVisualCubeEnv`, `orca-train-drqv2`, and existing visual checkpoints keep
  their current input and action shapes.

Full-orientation training uses explicit new configuration and a separate command.
No existing checkpoint is silently loaded into an incompatible observation space.

## Simulator Architecture

### Goal modes

`OrcaHandRightCubeOrientation` accepts:

- `face_direction`: the existing red-face-normal task.
- `cube_orientation`: a full `SO(3)` target quaternion.

For `cube_orientation`, MuJoCo quaternions use `wxyz` order. All externally
provided quaternions are normalized. The relative target is

`q_relative = inverse(q_current) * q_target`.

Its sign is canonicalized to make the scalar component non-negative. This makes
`q` and `-q` produce the same observation. Angular error is

`2 * acos(clamp(abs(dot(q_current, q_target)), 0, 1))`.

No cube-symmetry reduction is applied. The intended future physical cube must
therefore have distinguishable faces when full-orientation vision is introduced.

### Orientation targets

The simulator exposes the 24 proper axis-aligned cube orientations. Target
sampling excludes any orientation already within the success tolerance and
excludes the immediately preceding target.

Three target policies support the static curriculum:

- `fixed_quarter_turn`: one deterministic 90-degree rotation about the hand-frame
  X axis from the nominal initial cube orientation.
- `random_quarter_turn`: one uniformly sampled positive or negative 90-degree
  rotation about a hand-frame X, Y, or Z axis from the current orientation.
- `cube_orientation_bag`: shuffled bags containing all 24 axis-aligned cube
  orientations, with solved and immediately repeated targets skipped.

For the quarter-turn policies, the hand-frame axis is transformed into world
coordinates and the resulting delta rotation is left-multiplied onto the current
cube orientation. The orientation bag is generated by composing each of the 24
proper cube rotations, expressed in the fixed hand-mount frame, with the nominal
initial cube orientation. The nominal orientation is therefore a member of the
same target set.

Target completion reuses the existing sequence event model. A target switch resets
the angular-progress baseline against the new target so switching goals cannot
create reward.

### Reward and success

A new `angular_progress` reward mode computes:

`progress_reward_scale * (previous_error_rad - current_error_rad) - step_penalty`.

It retains the configured per-target success bonus and drop penalty. Existing
`absolute` and alignment-based `progress` modes remain unchanged.

Full-orientation success requires:

- Angular error within the configured tolerance.
- Cube height at or above the configured success height.
- Cube linear and angular speeds below their configured limits.
- The conditions to hold for the configured physical duration.

Drop continues to take priority over success and timeout.

### Physical-time configuration

`BaseOrcaHandEnv` exposes its effective control period as
`model.opt.timestep * frame_skip`. Cube-task construction may request a
`control_period_s`; the environment rounds it to the nearest positive integral
number of MuJoCo steps and reports the effective period.

The cube task additionally accepts `max_task_duration_s` and
`success_hold_duration_s`. It converts each duration to a positive number of
control steps using the effective period. Existing step-based arguments remain
available for compatibility. A non-`None` duration value explicitly overrides
the corresponding legacy step value; a `None` duration preserves the legacy
step behavior.

All info dictionaries expose:

- `control_period_s`
- `task_elapsed_s`
- `max_task_duration_s`
- `stable_success_duration_s`

Orientation mode additionally exposes:

- `target_quat`
- `relative_target_quat`
- `orientation_error_rad`
- `target_rotation_angle_rad`, measured when the target is issued
- `completed_target_rotation_angle_rad` on a completion event
- Existing sequence completion and termination diagnostics

## State Training Architecture

### Environment adapter

`OrcaStateCubeEnv` is independent of `OrcaVisualCubeEnv`. It retains the same
measured-state-relative joint action rule: each normalized action commands at most
the configured number of degrees relative to current measured joint position,
then clips to the joint ROM.

The adapter returns `{"state": vector}`. The vector contains, in order:

1. 17 actuator joint positions normalized by ROM.
2. 17 actuator joint velocities scaled and clipped by a configured limit.
3. Cube position expressed in the fixed hand-mount frame and scaled by the
   configured workspace radius.
4. Cube linear velocity in the hand-mount frame, scaled and clipped.
5. Cube angular velocity in the hand-mount frame, scaled and clipped.
6. The canonical relative target quaternion.

The resulting state has 47 float32 values bounded to `[-1, 1]`. Observation
construction is pure and does not mutate task counters.

### State agent and replay

The first baseline uses the deterministic actor/twin-critic core already used by
DrQ-v2, but without an image encoder or image augmentation. It consists of:

- A feed-forward MLP actor with bounded continuous actions.
- Twin feed-forward Q critics and a target critic.
- The existing exploration schedule, clipped target-action noise, soft target
  updates, and three-step returns.
- A vector replay buffer that stores only state, action, reward, discount, and
  next state.

The state agent is deliberately feed-forward. A later recurrent stage will add
sequence replay and burn-in rather than inserting an LSTM into one-step replay.

Checkpoint metadata includes observation mode, state dimension, action dimension,
agent configuration, and training step. Loading validates all three dimensions
and produces a clear compatibility error instead of a tensor-shape traceback.

### Training entry point

A separate `orca-train-state` command constructs a curriculum preset and records
its resolved simulator settings in `config.json`.

The presets are:

| Preset | Target policy | Sequence | Tolerance | Target duration | Hold | Control period |
|---|---|---:|---:|---:|---:|---:|
| `single_goal` | fixed quarter turn | 1 | 0.4 rad | 8.0 s | 0.16 s | 0.08 s |
| `right_angle` | random quarter turn | 1 | 0.4 rad | 8.0 s | 0.16 s | 0.08 s |
| `multi_goal` | orientation bag | 20 | 15 degrees | 8.0 s | 0.16 s | 0.08 s |

All use angular-progress reward. Preset fields remain individually overridable
from the CLI, but resolved values are saved so a run is reproducible.

Training does not automatically advance between presets. Promotion is an explicit
new run, which keeps results and replay distributions interpretable.

## Evaluation

Evaluation uses fixed seeds and reports:

- Mean return.
- Full-episode success rate.
- Mean and median targets completed.
- Total targets completed.
- Drop and timeout rates.
- Mean and median seconds per completed target.
- Mean final and best angular error.
- Per-target rotation-angle bucket results for 90, 120, and 180 degrees when
  present in the selected preset.

The first implementation is considered ready for long training only when local
tests pass and a short training smoke run demonstrates that replay insertion,
updates, evaluation, checkpoint save, and checkpoint load complete without error.
No claim about manipulation performance is made by the smoke run.

## Error Handling

- Reject zero-norm or incorrectly shaped quaternions.
- Reject unknown goal modes, target policies, curriculum presets, and reward
  modes.
- Reject non-positive durations and control periods.
- Reject a requested control period that rounds to zero MuJoCo steps.
- Validate state, action, and checkpoint dimensions at public boundaries.
- Preserve drop-first event ordering and prevent accessor methods from mutating
  counters.

## Testing Strategy

### `orca_sim`

- Quaternion sign invariance and known 90/180-degree geodesic errors.
- Relative quaternion composition and canonicalization.
- The 24 axis-aligned target orientations are unique.
- Fixed and random quarter-turn samplers produce the required separation.
- Orientation bags omit solved and repeated targets.
- Angular-progress rewards are exact and target switches give no false progress.
- Duration conversion gives 100 target steps and 2 hold steps at an 80 ms control
  period.
- Full-orientation success, timeout, sequence completion, and drop priority.
- Existing face-direction tests continue to pass unchanged.

### `orca_train`

- State observation ordering, normalization, bounds, and hand-frame transforms.
- Delta actions remain relative to measured joint positions and respect fixed
  joints.
- Vector replay allocation, sampling, and n-step boundary behavior.
- State actor/critic update behavior and checkpoint compatibility errors.
- Curriculum preset resolution and CLI override precedence.
- Fixed-seed evaluation aggregation.
- A short fake-environment training run covering metrics and checkpoints.

### Repository verification

- `uv run pytest tests/` in `orca_sim`.
- `uv run pytest` in `orca_train`.
- `git diff --check` in both repositories.

## Delivery Boundaries

Implementation changes land on feature branches in both repositories. They do not
modify or stop existing run directories, launch remote jobs, push branches, or
open pull requests without a separate request. The implementation handoff includes
the resolved test evidence and exact commands for the first `single_goal` run.
